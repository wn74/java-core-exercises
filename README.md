# Java Enterprise Fundamentals

Practical exercises for getting comfortable with Java after working primarily in Python and Rust.

> **Note on AI Usage:** AI was used only to write this README and to act as an interactive tutor while working through the exercises. None of the Java code in this repository was generated by AI.

---

## Overview

Python relies heavily on duck typing and dictionaries. Rust uses traits, pattern matching, and ownership rules. Java takes a very different path centered on class hierarchies, strict interfaces, built-in thread management, and the standard collections library.

This repository contains four standalone command-line exercises built using only the standard Java library. The goal was to build solid habits with core Java patterns before moving on to larger frameworks like Spring Boot:

* **Handling money correctly:** Understanding why `double` breaks financial math and how to use `BigDecimal` instead.
* **Transforming data:** Using Java Streams and `Optional` instead of standard `for` loops, list comprehensions, or null checks.
* **Wiring code together:** Writing interfaces and passing dependencies through constructors by hand to understand how Dependency Injection works under the hood.
* **Running tasks in parallel:** Managing background threads and thread-safe queues without data races or deadlocks.

## The Exercises

### Exercise 1: In-Memory Ledger
* **Topics:** `BigDecimal`, `RoundingMode`, custom exceptions, enums.
* **What it does:** Simulates bank accounts with deposits, withdrawals, and transfers. Floating-point types (`float` and `double`) introduce rounding bugs over multiple operations, so all balances use `BigDecimal` with explicit rounding. If an account does not have enough money, it throws a custom `InsufficientFundsException`.

### Exercise 2: Log Parsing Pipeline
* **Topics:** Records, `Stream`, `Collectors`, `Optional`.
* **What it does:** Reads raw log strings into immutable Java records. Using stream methods like `.filter()`, `.map()`, and `.collect()`, it counts errors per service and picks out the most recent error. Values that might not exist are wrapped in `Optional` instead of returning `null`.

### Exercise 3: User Service and Manual DI
* **Topics:** Interfaces, separation of concerns, constructor injection.
* **What it does:** Implements a user registration flow. A `UserRepository` interface defines storage operations, and an in-memory class implements it. The `UserService` does not create the repository itself; instead, the repository is passed into the service constructor in `main`. This is the exact pattern that Spring Boot automates with annotations like `@Service` and `@Repository`.

### Exercise 4: Warehouse Barcode Dispatcher
* **Topics:** `ArrayBlockingQueue`, `ExecutorService`, thread pools, clean shutdown.
* **What it does:** Implements a producer-consumer system. An operator inputs pallet barcodes into a fixed-size queue (capacity of 5). Two background worker threads pull barcodes from the queue at the same time and process them. When the operator enters an exit command, the dispatcher stops taking input, lets the workers finish whatever is left in the queue, and shuts down the thread pool without hanging.

## Running the Code

### Prerequisites
* Java Development Kit (JDK) 17 or higher installed
* Any text editor, IDE (IntelliJ, VS Code, Eclipse), or command line terminal

### Compile and Run
You can run any exercise directly from your IDE by running its `Main.java` file, or compile and run from the root folder in your terminal:

```bash
# Compile all source files into an 'out' folder
javac -d out $(find src -name "*.java")

# Run an exercise (example: Exercise 4)
java -cp out ex04_concurrency.Main
```
